Source of truth: installed data.pkr trigger banks, retail SpideyPC.exe command
decoder and CCamera methods, CoOp_SectionExecute/actor wrappers, and the
CPLAYER-28/29 diagnostics. Run tests/coop/validate_chase_banks.py to check

Bank graph and authored fixed-camera nodes:
  L3A1_T  -> L3A1a_T (branch) or L3A2_T; nodes 63,67,87,95
  L3A1a_T -> L3A2_T; nodes 51,55,68,69
  L3A2_T  -> L3A3_T; nodes 7,11,437,438; checkpoint node 355
  L3A3_T  -> L3A4_T; nodes 28,32
  L3A4_T  -> L3A5_T; nodes 7,11,74,88
  L3A5_T  -> L4A1_T (next regular bank); nodes 6,10,17,19
Every chase bank contains its own autoexec and restart node. The camera nodes
use opcode 186 except L3A1a nodes 68/69, which use 185. Opcode 185 calls
CCamera::SetFixedPosMode (mode 4); 186 calls SetFixedPosAnglesMode (mode 5).
Opcode 188, when used, calls SetFixedFocusMode (mode 6). These are event
directives, not a blanket camera mode for L3A2 or the entire chase. The
normal follow mode observed in both P1 and P2 gameplay snapshots is 3.

Retail Trig_ExecuteRestart places the single MechList CPlayer at the bank's
restart-node position/orientation, then executes that node's commands.
Trig_ExecuteAutoexec runs each bank's authored setup commands. The co-op
layer does not instantiate P2 from a second authored restart: it constructs
an independent retail CPlayer/CCamera after the native P1 exists, once the
camera is back in playable mode 3 (or boss mode 16), letterbox/pause are off,
and a 350 ms settling gate plus rear-footprint floor probe succeed. This is
why a chase bank can load before P2 appears. A failed rear probe is retried;
the new diagnostics distinguish that from missing model or camera resources.

The native level-change opcode is 305. Co-op runs a P2-triggered level change
in the shared world context and reconstructs both player/camera slots after
the new bank loads. A private P2 context must never be restored over a new
bank's resource pointers. P2 is deliberately joined after authored
letterboxing and only after a supported rear-footprint floor/clearance probe.
The CPLAYER-28 log reached L3A3 with both player/camera slots, including a
P2-initiated L3A2->L3A3 handoff. In L3A2 it recorded 37 unsuccessful spawn
attempts before P2 joined; that log did not record failure reasons. It did
not reach L3A4, L3A5 or L4A1. Those transitions are asset/code audited,
not live verified. The new log records the spawn failure reason for retest.

CPLAYER-29's installer had four chase vtable addresses offset by 0x400. Its
log says interactions: installed=0. Because the installer also owned the P2
camera update call, the second camera was constructed in mode 3 but never
ticked. CPLAYER-30 corrects the verified retail addresses and installs the
camera tick independently of AI/pickup guards. The bank-wide rotation copy
has been removed. P2 retains its native CCamera tripod and follows its own
player in ordinary chase gameplay.

Authored camera/scene commands are routed through CoOp_SectionExecute's
participant owner. Chopper, sniper target, searchlight and missile AI can
queue later trigger pulses outside a command list. Their wrappers now stamp
newly queued pulses with the living player selected for that actor's single
native AI tick, so later camera and gameplay commands run in that player's
context. Opcode 305 remains a shared level change. No command is replayed
twice. New diagnostics report independent camera update calls, mode changes,
authored camera command ownership, actor-generated pulses and spawn failures.

Manual verification needed in the isolated test copy: P2 follows normally at

CPLAYER-36 follow-up (2026-09-23): The latest live log showed that the ledge

2026-09-30 native entry-state handoff: the former hidden-P2 release required
a floor and forced Stand, even when retail handed P1 control while crawling
or airborne. The first construction attempt is now immediate when the
native player/camera exist; only failed allocations use the retry interval.
During an authored opening the hidden participant follows the actor's real
animation frame, fractional frame, position, orientation and velocity.

Level-entry and later scripted-motion releases use the same audited native
motion transfer. They preserve surface normals/basis, contact packets,
motion state/counters, velocity/acceleration, animation phase and camera
tuning. The recipient keeps its inventory, health, controller, costume/pose
allocations, target ownership and command allocations. Swing ropes and
look-around paths are separately constructed/copied rather than shared.
Retail's one-time floor/camera initialization flags follow the actor so the
recipient does not reset a valid crawling or airborne handoff to standing.

Control release waits for the actor's synthesized commands and letterbox,
not a standing animation, a floor probe or a particular camera mode. Ground
entries retain the checked rear placement; attached/airborne entries retain
the actor's known-valid origin if separation cannot be proved. This can
initially overlap the bodies but allows independent native control without
waiting for P1 to land. Later scripted handoffs support either event owner
and release after pending scripts/camera/skip cleanup have finished, using
the completed native exit transform. Dead/waiting partners are not revived
by this transfer. End captures now include animation phase, surface normal,
initialization flags and owned path/rope addresses for each participant.
