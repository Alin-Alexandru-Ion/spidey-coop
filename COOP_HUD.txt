Personal HUD

with P2's CPlayer/camera context. This reads the actual health/max health,
webbing, cartridge count, special web state, armor and costume portrait state.
The shared Sp, Compass and Webcart sprite resources are supplied to P2 at draw.
P2's health/head/web artwork reflects around its pane's right edge. The web
cartridge icon and ammo text move with that cluster but keep readable artwork
and glyph order. P1 keeps its original upper-left cluster in its own pane.

Compass, aim reticle, screen target markers and offscreen Spider-Sense are
owned by their player/view. Reticles are projected with the matching camera.
Spider-Sense is captured at its original AI-time invocation: drawing another
pane does not age the same indicator trails twice.
Simple messages created inside a player/trigger context carry a generation-
checked player owner. Unowned messages remain shared. Messages from deferred
scripts without a player context deliberately remain shared; identifying
additional mission-specific ownership requires auditing those script paths.

Common HUD

that pass. Transition fades execute once after personal HUD drawing. Existing

the timer/module callback. Message lifetime updates are unchanged.

CPLAYER-46 follow-up (2026-09-24): P1/P2 glyphs were present in the queue,
but all badge pieces shared DX7 slot zero. DXPOLY prepends each polygon, then
renders the slot in reverse insertion order; the dark background could cover
the lettering. Enqueue the background last so it renders first, then the
stripe and finally the explicit 5x7 white glyphs. Size one bitmap cell from
the full display height instead of the individual split pane: the minimum is
2 screen pixels at 480p and 4.5 at 1080p in either split orientation. The
head gap, pointer, edge arrow, and top-edge fallback scale with it. Tests
verify the P1/P2 pixels, queue layering, and equal 1080p scale for both
orientations. Live visual confirmation remains pending.
