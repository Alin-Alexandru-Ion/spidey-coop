Co-op coordinator: CPLAYER-5 (2026-09-13)

Current architecture
- The roster contains two CPlayer pointers with generation-stamped handles.
  Publish accepts CPlayer only; there is no standalone CSuper preview path.
  CPlayer still inherits CSuper in the original engine, as it should.
- P1 remains the retail player. P2 is constructed by retail 004B9EB0 with
  a new 0xEFC allocation and destroyed by retail 004C9210.
- P2 owns an independently constructed retail CCamera (00415EE0, size 0x2F4)
  and SControl (size 0x18C). Neither is a shallow copy of P1.
- Original CBody::Update (00460F90) advances P2 timing/animation and invokes
  its original CPlayer::AI (004C65C0), followed by the original camera update.
  CPLAYER-38 moved the P2 body tick to the shared player-list boundary so it
  can run even if P1 is waiting/dead. Render passes never replay gameplay.
  Pause, letterbox and foreground gates are retained.
- coop_motion.h and the custom yaw/follow camera have been removed.
  Key 7 pose mirroring has been retired: gameplay animation belongs to each
  CPlayer's state machine.

Legacy translation
- The registry/router is the authoritative two-player roster.
- The legacy MechList and CameraList remain P1 outside P2 execution. During
  P2 constructor/update/destructor calls, the context bank exposes P2's own
  single-player list heads/counts and restores the enclosing context afterwards.
  This accommodates the original constructor's count==1 invariant without
  disabling it or corrupting P1's intrusive list links.
- The context bank exchanges explicitly listed player/camera singleton storage,
  input aliases, animation timing, and player-owned effects. Overlapping ranges
  are merged so bytes are exchanged once. Mutable animation command pointees
  are banked too: copying only their pointer table would still corrupt P1.
- Shared actors, geometry/collision grids, world time and mission queues are not
  duplicated or replayed. Effects written into shared world lists remain shared.
- P2 constructor's BagHead call is skipped with a verified call-site wrapper,
  since it rewrites shared mesh vertices. P1 retains the original call.
- P2 destruction isolates its own effects and skips shared costume teardown
  and checkpoint inventory writes through scoped lifecycle state.
- Owned operations never fall back to the other player. Shared target/interaction
  queries support nearest, range, caller conditions, preferred target and health.
  These query helpers do not automatically intercept every retail gameplay call.

Controls
0 top row: force exit; 9: join/recreate nearby; 8: drop out.
6: cycle left/right, top/bottom, single view.
P2 arrows: movement; numpad 1: jump; 2: punch; 3: kick; 0: swing;
4: aim; 5: web; 6: zip. The entire set feeds the retail control structure and
state machine; retail action availability/geometry still determine outcomes.
Both physical button fields and the PC gameplay aliases receive matching input.
Initial P2 death policy is drop-out before another death-controller tick.

Validation and limits
- VS6 compilation and binary layout checks are required.
- tests/coop/run_router_tests.py exercises the production context bank,
  registry and retail adapter using redirected calls/storage, including
  lifecycle rollback, P1 restoration, per-player commands, input timing,
  render-without-simulation, death withdrawal and retained shared-world changes.
  It does not prove the original game's complete controller call graph.
- Projection/frustum tests execute isolated retail arithmetic only.
- Game is never launched by the agent. Runtime control/camera behavior, native
  action outcomes and distant-region visibility still require user testing.
- This is original-controller integration, not a claim that every singleton
  in every mission/enemy/trigger routine has already been converted. Outside
  scoped player calls, unadapted MechList consumers still see P1.
- Black-zone loading/visibility is not established fixed by this migration.
- Diagnostics identify CPLAYER-5 and record original-controller tick count and
  health along with both player and secondary camera positions.
